# AGENTS.md（项目工程执行规范）

## 一、沟通规范
- 默认使用中文回复。
- 禁止输出无关内容，保持表达简洁明确。
- 未经确认，不得擅自扩展需求或增加功能。
- 修改项目代码前，先阅读本文件和 `doc/项目开发规范.md`。

## 二、工作流程
- 简单任务可以直接执行：小范围修改、明确指令、不改变接口协议、数据结构或核心流程。
- 复杂任务必须先出方案，确认后再修改：涉及多个模块、3 个及以上文件、接口协议、数据结构、核心流程、架构调整或新增依赖。
- 需求不明确时必须先提问，禁止猜测实现。

## 三、编码规范
- 严格保持原有代码风格。
- 不擅自重构代码结构。
- 不调整无关代码。
- 默认不写注释，仅在复杂逻辑或隐含业务规则处补充。
- 禁止硬编码密钥、Token、数据库密码和私密配置。
- 禁止新增依赖，除非已说明用途、替代方案和风险并获得确认。

## 四、分层规范
依赖方向：

```text
api -> service -> repo -> model
```

- api 仅处理请求、参数校验、调用 service、返回响应。
- service 仅处理业务逻辑和业务规则。
- repo 仅处理 SQL 和数据访问。
- model 仅表示数据库结构。
- types 仅表示请求和响应结构。

## 五、文档同步
以下情况必须更新 `doc/`：
- 新增或修改接口。
- 修改请求或响应结构。
- 修改数据结构。
- 修改核心流程。
- 修改错误码。
- 修改配置项。

## 六、禁止行为
- git commit。
- git push。
- 自动部署。
- 修改 CI/CD 配置。
- 未确认引入新技术栈。
